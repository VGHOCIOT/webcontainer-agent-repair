# webcontainer-agent-repair
Self-healing autonomous micro-SaaS builder that has its own runtime as an agent that detects and patches breaks without a backend

## Run it

```
npm install
npm run dev        # open the printed URL
```

Enter an Anthropic API key in the UI (or set `VITE_ANTHROPIC_API_KEY` in `.env`). Everything runs in the browser tab: the app code is generated by the model and executed in an in-browser Node.js sandbox (WebContainers), with no server-side execution.

Other commands: `npm run build` (typecheck + bundle), `npm run lint`, `npx tsc -p tsconfig.app.json --noEmit` (typecheck only). There is no test runner; the signal is running the agent loop.

## What a batch compares

A batch runs each run index in several **arms**, all scored by the same qualified graders (a model-authored validator and, for frontend specs, an interaction driver) with the same attempt cap:

- **healing**: each retry sees the previous code and the real captured error.
- **spec-only**: the control. Every attempt is a fresh sample that sees only the spec.
- **informed** (opt-in): fresh samples that also see the grader's check names, which separates "told the requirements" from "debugged the error".

Graders are checked against a hand-written reference app and known-bad variants before they score anything (`src/lib/qualify.ts`). See `CLAUDE.md` for the architecture and `docs/EXPERIMENT.md` for the experiment design, fixed settings and validity rules.

## Getting results out

Nothing is stored. After a batch, use **Download results (JSON)**. Summarise one or more exports offline:

```
node scripts/analyze.mjs results/*.json
node scripts/analyze.mjs results/*.json --json
```

The script reports per-arm convergence with 95% Wilson intervals, the disclosure / debugging / total-feedback gaps with a separable-or-not verdict, cost, first-failing checks by layer, and warnings (unqualified graders, mixed graders, small N).

## Known limitations

- **Custom specs run on unqualified graders.** The preset specs and the built-in corpus have hand-written reference apps that the model-authored validator and interaction driver must pass (and must fail when the app is deliberately broken) before they are allowed to score anything. A spec you write yourself has no reference, so its graders are unverified; in testing, fewer than half of freshly authored graders qualified on the first try. The app flags this in the batch results and the export, and marks any check that fails in every attempt as a possible grader defect. Treat results on a custom spec as indicative, not as findings. This is an accepted trade-off, see `CLAUDE.md`.
